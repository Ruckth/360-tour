## Ownership and unchanged contracts

The plan's five rules, nine-domain map and Phase 3b plus prior POS and Services-closure evidence govern this helper-only change. POS owns order lines/links/counters, receipt/refund/lifecycle guards, manager-approval state and customer display projection. Seven actual ctx implementations move from lib into `pos/private`; their original lib files are deleted, with no compatibility endpoints or re-export stubs. Cross-domain production consumers (Bookings, Services, root maintenance and fixture support) use explicit named helpers from `pos/model.ts`. POS endpoints and implementation helpers import their actual private dependencies directly. Every operation receives the caller's ctx and keeps its existing transaction. No new RPC invocation, wrapper implementation, `ctx.runMutation` boundary, provider call or authorization bypass.

All **381 public/internal registrations**, including all 77 POS registrations, retain paths, names, builders, capability/reason, validators, args/returns and full handler syntax. All **ten HTTP actions** and route composition are unchanged. No registration is added, renamed or removed. Inventory remains **295 explicit public / zero raw**. `pos/model.ts` exposes the actual order-line/link/source/counter helpers needed by cross-domain production consumers; POS-only refund, lifecycle, display and approval helpers remain private. Four unused command/approval export groups (`lineCommands`, `paymentCorrections`, `paidLinks`, `approvalModel`) are retired from that interface: every actual endpoint already calls those private implementations directly. Keeping those exports would create `POS model → Bookings/Services model → POS model` runtime cycles after the ctx ownership move. Their definitions, public/internal endpoints and real callers are unchanged. The unused customer-helper export group is also retired from the cross-domain interface: there is no production caller outside POS, and re-exporting it would unnecessarily pull the existing backend-to-src phone dependency into Bookings' schema-validator import graph. The customer correction tests now import the same actual private functions and retain every assertion. The root follow-up also removes unused type/display/counter/order exports. Tests import the unchanged private declarations directly; no helper behavior is removed. The final interface exports twelve helpers actually used by other backend modules. `nextCounter` remains for the existing cross-domain fixture factory, which allocates only the order counter; `RECEIPT_COUNTER` is private to POS.

The narrow model surface also keeps `isOpenOrder`, `isSettledOrder` and `orderPaymentRecord` in their original cohesive implementations, now `pos/private/orderLinks.ts` and `pos/private/orderLifecycle.ts`. Auth and Marketing consume those plain functions through `pos/model.ts`. No runtime pure leaf needs extraction in this closure: avoiding unused command/customer/refund/approval exports eliminates the model cycles and schema import spill. Broader pure-leaf cleanup remains Phase 3c.

Browser display contracts (`DisplayLine`, `DisplayCoupon`, `DisplayOrderState`, `DisplayState`, `DisplayDriver` and the structural `Shared` alias) live in type-only `shared/displayTypes.ts`; their exact types are preserved. Shared is exported solely so the backend projection can use its original annotation. Browser files import no backend model/private modules.
