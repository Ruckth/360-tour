The **backend-only `convex/lib/adminEmails.ts` configuration leaf is owned by Auth**. Retaining this existing independent deployment-configuration leaf is the narrow cycle break. Auth, Marketing and Settings use the same implementation. No detector, boundary target, environment behavior or permissions are weakened; no generic policy injection layer is added. The preceding backend-only `lib/maintenance.ts` leaf remains unchanged.

An actual additional graph cycle appeared after moving the admin helper: `marketing/model → reportRead → lib/serviceSlots → auth/model → marketing/model`. Marketing reports only needed the pure `resortLocalParts` function from the mixed service module. Only that function and its existing `RESORT_OFFSET = RESORT_OFFSET_MS` binding moved, unchanged, to `shared/resortLocalParts.ts`; existing consumers now import the single implementation. It reads neither ctx nor process.env and imports only the existing pure date offset. All appointment authorization/creation, roster reads, validations and other serviceSlots declarations remain in place. Broader pure date/service cleanup remains Phase 3c.

Marketing retains actual `marketingGrants` endpoints and permission policy. Settings retains cashier-rule configuration/read policy, configuration history and record-history writing/projections. POS retains approval payloads/fingerprints/execution, order behavior, receipt/history projections and refunds. The mixed `lib/staffTypes.ts` validators/constants/payloads and `lib/staffApprovalState.ts` stay in place, apart from the latter consuming identity through Auth/model. No incidental other-domain endpoint move, product/schema/data/dependency/policy/money change is introduced.
