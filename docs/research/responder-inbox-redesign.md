# Responder inbox redesign — research and preview plan

Researched: 2026-09-30. ขอบเขต: ปรับหน้าจอในภาพให้คนตอบแชตเลือกงาน อ่านข้อความ และตอบได้ง่ายขึ้น พร้อม HTML prototype 3 แนวทาง ใช้ข้อมูลจำลอง ไม่ใช่การเปลี่ยน backend

## สิ่งที่เห็นจากภาพ

- Setup banner อยู่เหนือพื้นที่ทำงาน ทั้งที่เป็นงานของผู้ดูแลระบบมากกว่างานตอบแชต
- มีตัวเลือก 2 แถว: Needs reply / Live / All / Inactive และ Open / Resolved / Archived ซึ่งผสมสถานะงานกับการออนไลน์ของลูกค้า
- Header ใช้พื้นที่มาก และแสดง Reopen, Archive, Take over พร้อมกัน แม้บทสนทนานั้น Resolved แล้ว
- รายการซ้ายบอกว่าไม่มี Archived chats แต่ด้านขวายังคงแสดงบทสนทนาเดิม ทำให้ไม่ชัดว่าอยู่ในคิวใด
- กล่องตอบปิดใช้งาน และมีคำอธิบายยาว แต่ไม่ช่วยเลือกขั้นตอนถัดไป

นี่เป็นการประเมินภาพเดียว ยังไม่มีข้อมูลความถี่ใช้ฟีเจอร์หรือการทดสอบกับเจ้าหน้าที่จริง

## HTML preview 3 แนวทาง

1. **A — Calm inbox / แนะนำเริ่มต้น**: พื้นสว่างอุ่น 2 คอลัมน์ รายการคิวซ้ายและแชตขวา ใช้ Waiting / Open / Done; สถานะย้อนหลังและช่องทางอยู่ใน filter เพิ่มเติม เหมาะกับทีมที่เลือกหลายบทสนทนาเอง
2. **B — Focus mode**: พื้นมืด บทสนทนาเดียวอยู่กลางจอ คิวเปิดเป็น drawer พร้อม Resolve & next เหมาะกับเจ้าหน้าที่ที่ตอบต่อเนื่อง แต่ยังย้อนเลือกเคสเองได้
3. **C — Queue desk**: ตารางแสดง guest, channel, latest message, เวลาและสถานะ; เลือกแล้วเปิดแผงตอบทางขวา เหมาะกับการเห็นภาพรวมงาน หลีกเลี่ยง metrics ของผู้จัดการในหน้าตอบ

ทั้งสามใช้ข้อมูลและ interaction เดียวกัน เปลี่ยนโครงสร้างและลำดับความสำคัญ ไม่ใช่แค่สี. HTML ที่ทำจริงอยู่ใน `public/prototypes/responder-inbox.html`; แผน implementation และข้อจำกัดใน [responder-inbox-redesign.md](../plans/responder-inbox-redesign.md).

## แผนตรวจ prototype

- เริ่มที่เคสรอตอบที่ยังส่งข้อความได้ เลือกแชตและพิมพ์ส่งจำลองได้ โดยไม่ส่งข้อมูลจริง
- มีตัวอย่าง WhatsApp หมดเวลา และเคส Resolved เพื่อดูว่าปุ่มและคำอธิบายเปลี่ยนตามบริบท
- เปลี่ยนคิวหรือค้นหาแล้วแชตที่เลือกต้องสอดคล้องกับผลลัพธ์ หากไม่มีผลลัพธ์ แสดง empty state ทั้งสองฝั่งอย่างชัดเจน
- ข้อมูลลูกค้า ตัวกรอง และเมนูเพิ่มเติมเปิดและปิดได้; “ส่งและปิดเคส” ไม่ควรทำงานโดยไม่ตั้งใจ
- เปิดบน desktop และ mobile: mobile แสดงรายการหรือแชตทีละหน้า พร้อมปุ่มกลับ; กล่องตอบยังเข้าถึงได้
- ประเมินกับคนตอบจริง: หาเคสรอตอบได้เร็วไหม ส่งคำตอบได้กี่ขั้นตอน แยก “รอตอบ / รอลูกค้า / ปิดเคส” ได้ไหม และทราบวิธีดำเนินการเมื่อส่ง WhatsApp ไม่ได้ไหม ไม่มีการอ้างเปอร์เซ็นต์ประสิทธิภาพที่ยังไม่วัด
