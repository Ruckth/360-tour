# Stock workflows in Ease POS, Dr.Ease, and BookEase

Research and design proposal, 27 November 2026. The review used published product guides and checked-in UI and backend code. Source revisions are listed below. Deployment and tenant settings were outside the review. The [interactive proposal](../plans/stock-workflows.html) shows the page diagram and example journeys.

## Ease POS

The account menu opens **Stock** at `/inventory`. The default view is **Balances**, with a branch selector and five tabs. The two-step receiving sheet is a good reference for BookEase because it collects a whole delivery and posts it on one save. The item row already supplies the branch and item for contextual actions. [Stock overview](https://easepos.co/help/stock/overview) · [Receiving guide](https://easepos.co/help/stock/receive) · [Item detail source](https://github.com/atiz-official/ease-international/blob/da4b0bf28/src/app/%28app%29/inventory/ItemDetailSheet.tsx#L78)

| Tab | Staff actions |
| --- | --- |
| **Balances** | Search or scan by item, SKU, or barcode. Inspect on-hand and sellable quantities and open lot details. Receive one or several items, post a signed adjustment, or write off stock. Receiving can capture lot, expiry, and unit cost. [Stock overview](https://easepos.co/help/stock/overview) · [Stock guides](https://easepos.co/help/stock) |
| **Count** | Start a full branch or selected-item count, enter actual quantities, then review differences and confirm with a reason and approval permission. [Count guide](https://easepos.co/help/stock/count) |
| **Transfer** | Create a draft, send it from the source, then receive it at the destination. Sending lowers the source balance. The destination gains what is received. Partial receipt is supported. [Transfer guide](https://easepos.co/help/stock/transfer) |
| **Movements** | Review signed stock changes by item and branch, with operator, time, and operation type. [Movement source](https://github.com/atiz-official/ease-international/blob/da4b0bf28/src/app/%28app%29/inventory/MovementsTab.tsx#L114) |
| **Exceptions** | Review and close issues such as a negative balance or oversale. Closing records acknowledgment. Quantity corrections use stock actions. [Exceptions source](https://github.com/atiz-official/ease-international/blob/da4b0bf28/src/app/%28app%29/inventory/ExceptionsTab.tsx#L28) · [Resolution write](https://github.com/atiz-official/ease-international-backend/blob/28599b26e/internal/repository/postgres/inventory_repository.go#L2757) |

The backend writes the balance and movement together and reuses an operation identity on retry. Its lot allocation, reservation, and expiry rules explain why physical and sellable quantities can differ. BookEase can start with one on-hand number for retail goods without holds or expiry rules. [Movement writer](https://github.com/atiz-official/ease-international-backend/blob/28599b26e/internal/repository/postgres/inventory_writer.go#L320) · [Inventory repository](https://github.com/atiz-official/ease-international-backend/blob/28599b26e/internal/repository/postgres/inventory_repository.go#L1468)

## BookEase design

Add **Stock** to Admin. **Balances**, **Activity**, and **Products** are tabs within it. The working branch scopes balances and activity. Products stay shared across branches, with product editing restricted to authorized roles. Checkout and Receipt keep their existing entry points.

| Place | Actions |
| --- | --- |
| **Stock › Balances** | Search by product name or SKU. Show variant, on hand, and needs-recount state. Open Receive for one or several variants. Count one or selected rows. Adjust one row with the variant and branch already filled. Open item-filtered activity from the row. |
| **Stock › Activity** | Filter by date, item, or event. Read before and after, change, staff member, time, and reason. Link to the source delivery, adjustment, count, or receipt where available. |
| **Stock › Products** | Create a simple product with a default variant. Show variant controls when needed. Edit price and SKU, archive products, and open a prefilled Receive sheet after saving. Stock opening balances are posted through Receive so they have an audit entry. |
| **Checkout** | Look up the actual selling branch's stock. Add the default variant directly or choose a variant if needed. Take payment through the existing flow. Ask for physical-stock confirmation on a shortage before collecting, then flag the discrepancy for recount. |
| **Receipt** | Pick the goods and a condition to reuse the existing return flow. Show the restock effect and the original branch in review. |

| Job | Shortest normal path from the page |
| --- | --- |
| **Receive** | Open Receive and pick items if unset → enter quantities and save once. |
| **Count** | Open the selected balance rows and enter actual quantities → review the difference and post. If the balance changed, refresh and review or recount the affected rows. |
| **Adjust** | Open Adjust from an item → enter signed change and reason, then save. |
| **Sell** | Add an item → complete payment. The stock movement is automatic. |
| **Return** | Select the item and condition → complete the existing return. Approval and payout steps depend on the receipt. |
| **Transfer, later** | At origin, enter items and send → at destination, confirm what arrived. The origin and destination each record their own handoff. |

### Build order and acceptance

1. **Stock workbench.** Use one balance per branch and variant. Each posted action changes the balance and logs a movement in one transaction. Repeat a request with the same operation key to verify the same outcome without another movement. Check revocation, branch isolation, and stale count revisions. Test that a zero-variance count clears a recount flag with an audit record.
2. **Checkout pilot.** Seed real opening stock at the pilot branch before enabling sales. Check that a paid sale deducts once, a cancelled unpaid cart leaves stock alone, and a sellable return adds back once at the original branch. Test shortage confirmation on the actual payment path and pin the correct branch before any multi-branch expansion.
3. **Additional inventory needs.** Add transfer custody where branches ship independently. Use lot and expiry tracking before onboarding goods that require traceability. Add scheduled counts, approvals, material recipes, or purchasing only where an operating workflow requires them.

## Purchasing

Scope is branch replenishment for stocked retail variants. A purchase request (PR) records an internal request to buy. A purchase order (PO) records the commitment to a supplier. A goods receipt records what arrived and was accepted at the destination branch. These are three distinct records even when one employee handles the entire purchase.

### BookEase recommendation

- **Reuse Receive from Balances and Orders.** Keep direct receiving for opening stock and permitted purchases without a PO. For a PO-linked delivery, prefill the issued order’s branch and open lines. Use one supplier and one destination branch per PO. Draft orders stay editable. After issue, record amendments to price, expected date or outstanding quantity as a new version and keep prior versions. If the supplier, destination or item changes, cancel the affected remainder and issue the correct order. The buyer shares issued versions through the existing supplier channel.
- **Post only accepted units.** Review ordered, previously accepted and outstanding quantities by line. Save each delivery separately with a BookEase receipt ID and a packing-slip reference when available. Record damaged or rejected items as exceptions without adding them to on-hand. Leave shortages open until fulfilled or explicitly closed with a reason. Set aside excess or substitute goods until the buyer resolves the discrepancy. For 12 ordered and 5 accepted, on-hand rises by 5 and 7 remain open. Closing those 7 changes only the incoming quantity.
- **Use linked events for safe corrections.** A receiver can fix entries before posting. After posting, an authorized staff member records the reason and reverses the erroneous quantity against the original receipt line. Reversing 2 of the 5 posted units reduces on-hand by 2 and raises the open quantity from 7 to 9. If a remainder was explicitly closed, keep it closed and record the corrected quantity as cancelled. For a wrong variant or branch, reverse at the original branch and variant, then post the correct receipt with the applicable branch permission. A physical supplier return removes previously accepted units when they leave the branch. The replacement, if needed, uses a separately authorized order linked to that return. Cap the sum of corrections and returns at the line’s posted accepted quantity. A correction that would drive on-hand negative needs a stock lead, count evidence, and a follow-up count. Use Count or Adjust for a balance discrepancy unrelated to a specific purchase.
- **Tie the documents to the existing branch ledger.** PR approval and PO issue have zero on-hand effect. Post the receipt or reversal, linked movements, balance and PO quantities in one mutation. Validate the current branch authorization and quantities at posting, and apply branch scope to the document and activity reads. A retry with the same operation key and payload returns the original result. A different payload using that key is rejected. Surface a matching supplier slip for review even when a new key is used. BookEase already stores branch/variant balances and source-keyed movements. Purchasing needs its own movement types and a branch access check on stock history. ### Pilot sequence and evidence fit

1. **Prove receiving and correction in the stock workbench.** Use one branch and ordinary unit-counted variants. Verify whole-delivery posting, an original receipt plus a linked correction, duplicate submission and denial after branch access is revoked. Keep the existing checkout pilot gate. Koh Samui is the current checkout stock branch, so validate the selling branch before expanding sales. [Checkout branch selection](../../convex/pos/private/paymentCommerce.ts#L97-L99) · [Default branch](../../convex/commerce/ensureDefaultBranch.ts#L5-L20)
2. **Pilot direct POs and partial receiving with one supplier.** Exercise a split shipment, damage, closing a shortage, competing receipts for the same remainder, and a correction after a sale. Verify a further correction after short closure leaves the order closed. Reconcile PO quantities and branch Activity against the delivery paperwork. Agree on how staff record physical supplier returns and replacement decisions. Vendor bills, supplier credits and payments stay with the existing accounting process.
3. **Add PR approval when staff need an internal handoff before ordering.** Start with one approval for the whole request, a requester and a different authorized reviewer. Record the branch, lines, reason and decision. Link PO lines to the approved request lines. Charge each PO against remaining approved quantities when it is issued, and release cancelled quantities for reuse while the request is open. Verify that two buyers cannot each order 6 units against the same approval for 10. Keep direct POs where the branch authorizes purchases without a PR.

**Evidence fit is 8/10 for the proposed single-branch stock pilot.** The primary guides cover the document boundaries, partial receipts, closing a remainder and safe correction. The BookEase schema and checkout writer support the proposed branch ledger approach. Before launch, confirm who may issue, receive and reverse at the pilot branch, and trace one real supplier order and packing slip through receipt and correction.
