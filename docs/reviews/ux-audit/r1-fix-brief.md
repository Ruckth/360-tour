# Round 1 fix brief — get every screen to 9+

Sources: `r0-checkout.md`, `r0-desk.md`, `r0-admin.md` (Opus graders) and `r0-codex.md` (independent gpt-6.1-sol grader), all against `scorecard-rubric.md`. Read the report for your area before starting; this brief settles the conflicts and is the order of work. Where a report and this brief disagree, follow this brief.

## Rules for all packages
- Visual, copy and interaction only. Keep every money safeguard: attempt/idempotency keys, revision checks, approval flows (`NEEDS_APPROVAL`/`PENDING_APPROVAL`), satang caps, permission gates. A dirty-draft guard must never bypass a revision check.
- No new dependencies. Reuse `ui/` primitives (`card`, `toggle-group` `variant="segmented"`, `select`, `combobox`, `dialog`, `skeleton`, `info-tip`, `stat`, `time-picker`, `disclosure`, `more-menu`). Money is always `.money` / `font-sans tabular-nums`.
- Touch targets ≥ 44px on touch (`pointer-coarse:min-h-11` or `min-h-11`); icon buttons have `aria-label`; visible text and accessible name match (WCAG 2.5.3).
- Unsaved-draft guard pattern (B and C): one shared `useUnsavedGuard(dirty)` hook that registers `beforeunload` and returns `confirmDiscard(): Promise<boolean>` showing a `Dialog` ("Discard unsaved changes?" · Keep editing / Discard). Package C creates it at `src/hooks/use-unsaved-guard.tsx`; Package B creates the same file with the same API if C hasn't landed — the integrator keeps one.
- Ownership, to avoid merge conflicts: A owns `src/components/checkout/**` and `src/lib/staff-approvals.ts`; B owns desk/calendar/chat files in `src/components/admin/` and `src/components/reui/event-calendar/**`; C owns `AdminSettingsView`, `TeamSettings`, `SegmentedTabs`, `src/components/admin/marketing/**`, `src/components/ui/**`, `src/app.css`. Don't edit files outside your package; if you need a shared change, inline it and note it.
- Update unit/browser tests whose copy or roles changed; never weaken an assertion about money, approvals or permissions.
