Compiler scripts use the native alias's explicit path to avoid ambiguous shared `tsc` binary names.

The initial cold Node 22 `check:fast` took 55.16s. Cached runs are the intended inner loop; a first ESLint cache fill remains more expensive. The requested 30-second target is a warm/idle target, not a guarantee under machine load.

End-to-end `verify` passed again, including all 3267 tests, lint/types and the production build; only the outer runner acquired a slot.

## Queue demonstrations

Two concurrent `HEAVY_SLOTS=1 node scripts/heavy.mjs sleep 3` commands used an isolated temporary `HEAVY_DIR`:

```text
first: heavy: acquired slot after 0.0s
second: heavy: waiting for slot (1 busy: sleep 3)
heavy: acquired slot after 3.0s
```

Killing a holder with SIGKILL (`kill -9`) left a dead PID; the next command reclaimed its slot immediately (`heavy: acquired slot after 0.0s`). The orphaned demonstration sleep was explicitly terminated. A nested heavy invocation acquired only once. While `verify` was inside its nested full unit suite, inspecting this checkout’s owner files found exactly one slot, owned by the outer verification runner. Further checks confirmed child exit code 7 is preserved, SIGTERM is forwarded and exits 143 with slot release, and CI=1 / HEAVY_SLOTS=0 run without touching queue storage. Temporary queue directories were removed.

## Corrections and limits

- The first implementation check found a test-only `ProcessEnv` typing mismatch because Next augments it with mandatory `NODE_ENV`. The queue helper accepts only the environment string map it actually needs; the corrected TS 7 and TS 5.9 checks pass.
- Knip initially reported `tests/browser/vite.config.ts` unused after wrapping Playwright. Explicit Playwright config discovery fixed the real discovery regression; nothing was ignored.
- Existing shared-checkout public backend/Clerk build configuration was selected into an ignored mode-600 worktree `.env.local`; no deploy key or outbound-provider credentials were copied. Build validation reads the configured backend; it does not start or seed one.
- The production build exited 0 and logged `Skipping validation of types`, but the existing configured backend is behind this source tree. Representative warnings, preserved verbatim:

  ```text
  [villas] list failed; serving the last good result for 30s Error: timed out
  Could not find public function for 'catalog/publicProperties:featuredReviews'.
  ```

  No backend deployment or application fallback change was made. Build timing is therefore limited by this existing backend/configuration mismatch and does not prove populated-catalog rendering.
- Vercel's wrapper still invokes queued `pnpm build`; Vercel's `CI=1` is inherited and bypasses the local semaphore, so no raw build command is needed. Nested local integration calls similarly inherit `HEAVY_HELD`.
- Phase-gate integration, component/browser and E2E suites were not requested for this verification and were not run. Their scripts are queued. No persistent dev server or Chromium session was started; temporary Vitest/Vite inspection contexts were closed.
- Raw verification logs and the comparison chart remain in ignored `output/dev-speed-phase1/`. No unit/guard test failures occurred. Temporary floating-promise fixture failures are intentional assertions, not suite failures.
