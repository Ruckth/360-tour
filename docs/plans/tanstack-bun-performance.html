Decisions

When is a destructive change worth making?

There are no real users. A compatibility window can be omitted when the source of truth and a reproducible recovery path are known.

Recommendation Choose the simpler schema when the matched experiment meets its read/write targets. Use a named disposable dataset for rehearsal and preserve a matched application/data rollback for any shared cutover.

  • Reduce measured database reads and bytes
  • Rehearse cutover and prove the gains

Which TanStack packages belong in the first slice?

The app needs routing, SSR and head/status control. Convex already owns live queries.

Recommendation Adopt Start and Router. Add Query only to a loader that demonstrates a useful SSR-to-live handoff, with request isolation, freshness and subscription counts verified.

Measure navigation to a responsive panorama

  • Benchmark gap
  • Wave 1

Start on /rooms/pool-villa?tour=1. A visitor succeeds when a drag turns the visible panorama. This is the first implementation ticket.

Scenario

Current behavior

A visitor follows a shared tour link

  1. Room page loaded
  2. Click
  3. Controls

The historical timer starts after the room page has loaded, when the test clicks Explore 360.

The visitor drags the panorama

  1. Controls visible

The controls text ends the historical timer. Input response is unobserved.

Proposed behavior

A visitor follows a shared tour link

  1. Direct link
  2. SSR and hydration
  3. Scene data

Start the timer at navigation and record HTML, hydration and the first scene request.

The visitor drags the panorama

  1. Room on screen
  2. Drag
  3. Changed frame

A trusted drag changes the camera and a rendered frame shows the new view. Save elapsed time and the trace.

Cause and evidence

On 3 October the prior benchmark reported a cold median of 6,628 ms from click to controls and a warm median of 1,860 ms (five each). Its one cold image was the 710,658-byte master. Today the mobile harness expects the versioned 2048 derivative. It opens the page before timing a click and counts completed responses only. Neither archived number measures today’s navigation or first input.

  • tests/bench/tour-open.bench.ts
  • docs/plans/benchmarks/final-tour.json

Proposed fix

  1. Extend tour-open.bench.ts with direct URL navigation, click after page load, and same-page reopen as separate cohorts. From navigationStart or actual input, mark SSR response, hydration, viewer module ready, first live scenes result, request start/end, decode, texture upload/first scene draw, trusted drag and first rendered frame with changed camera orientation. Keep the old click-to-controls series. Assert requested and shown IDs match, then compare camera yaw and the canvas across the gesture. Record failures and timeouts as failures. Use CDP Input.dispatchTouchEvent to send a fixed touch drag. A benchmark-only frame probe records yaw and the frame number inside the render cycle. Compare browser-composited screenshots cropped to the canvas to catch blank frames without enabling preserveDrawingBuffer. Timestamp in the render probe so screenshot capture stays outside the measured interval.
  2. Capture a browser trace and server durations with per-run IDs. Distinguish server cache hit/miss, Convex execution from transport/subscription startup, and network from decode/GPU. Count in-flight and completed panorama requests before input. Attribute overlapping spans on the critical path once. Automate the gesture as soon as the scene is ready to exclude human think time. Read the sanitized function execution spans from the isolated harness backend.log or add a duration mark to the measured handler in the benchmark build. For SSR expose a Server-Timing duration. Match durations via run IDs without subtracting wall clocks across processes.
  3. Use the local production-build harness and demo-resort fixture. With dedicated Clerk test configuration loaded, create output/tour-perf and run from the repository root: 
    node scripts/heavy.mjs node scripts/local-integration.mjs -- \
  env BENCH_RUNS=5 \
  BENCH_OUT="$PWD/output/tour-perf/control-smoke.json" \
  pnpm bench:browser tour-open
    Pass BENCH_* inside the child command because the harness filters its environment. Use unique JSON paths for each variant and batch and inspect the recorded runs and profile before comparison. Extend the harness to emit all new cohorts before freezing the baseline. Match 390×844, DPR 2, touch, CPU 4×, 1.6 Mbps down and 150 ms RTT, fixed browser and software WebGL. Log commit, lock, fixture hash, device, cache state, runtime and asset hash.
  4. Repeat paired control/candidate runs in alternating order, 20 observations per variant per cohort across two batches. Report raw samples, median and nearest-rank p95, errors and sample counts. Isolate browser cold vs warm and server miss vs hit. With candidate and control on the same build, vary one factor (e.g. seed scene count or delayed texture fetch). Require the predicted span and the end-to-end time to move together. Reverse the change to confirm.
  5. The local integration harness disables Convex log tailing. Use benchmark-only handler timing marks, or enable sanitized per-call logs in the benchmark profile and verify that each run has an observed duration.

Acceptance checks

Attach reproducible raw runs, trace, sorted critical-path spans, one repeatable intervention and a signed-off budget to the first ticket. Proposed target is ≥20% lower cold direct-entry median versus the newly measured control, with warm median and cold p95 within +5%, zero failed opens and no drift outside the budget in either batch. If noise exceeds 5% rerun matched batches and report inconclusive results before crediting any gain. Define noise as a >5% difference between repeated control medians on the same setup. If p95 flips the verdict across batches, expand to 50 paired observations per batch and publish both distributions. A remaining disagreement is inconclusive.

Move the route tree to TanStack Start

  • 32 pages · 3 API handlers
  • Wave 2

Prove one room route on the deployment target before moving booking, messaging and staff workflows.

Cause and evidence

The room page shares a cached server detail read with metadata. RoomDetailClient opens a browser-only viewer and synchronizes ?tour=1. Next also owns middleware, server caching, image transforms, metadata, redirects and the three HTTP handlers. A router-only swap leaves those behaviors without an owner.

  • Start migration guide
  • Clerk Start SDK
  • Convex with Start
  • Vercel Start adapter
  • Vercel Runtime Cache API
  • Vercel image configuration
  • Sentry for Start

Proposed fix

  1. Inventory the 32 tracked page.tsx files (10 localized, 18 admin, sign-in, sign-up, display and dev preview), three route.ts files, layouts, special routes and redirects. Create a URL-by-URL parity table with anonymous/staff results, HTTP method/status, cache headers, metadata, locale and test. Inventory next/*, next-intl, Clerk, Sentry, image/font, instrumentation and test mocks. Include messages/commerce and messages/display. For every URL also record actual production HTML with JS disabled, prerender vs SSR, cache hit/miss, hit ratio and TTFB. Inspect the built room page to establish whether the Suspense fallback or villa content is sent.
  2. Use a long-lived migration branch with two build entries. Main keeps shipping the existing Next app until the switch. In the branch, keep the shipping entry intact. Build each migrated slice in an isolated Start entry and share only framework-independent domain and UI code. Split Next-bound components into pure views and small route-specific wrappers as they move. CI builds both entries during overlap and rejects next/* imports reachable from the Start entry. Remove the legacy entry after accepted cutover.
  3. Build a separate candidate entry on the migration branch using TanStack Start, Router file routes and Vite, with the Vercel-supported Nitro Vite deployment adapter. Cache only anonymous raw villa data by deployment/slug with 60 s revalidation, then localize per request. Preserve existing last-good, known-inactive, 3 s deadline and 30 s backoff semantics. A 3 s deadline or transport error serves the last confirmed detail, then an eligible cached catalogue row. A cold unknown slug returns a temporary error. An authoritative null evicts last-good detail and records a miss so a stale catalogue cannot resurrect it. A confirmed reactivation clears its marker. A successful fresh read replaces the old snapshot. A new process starts with empty fallback state. Scene subscriptions and private data never use this fallback.

Map NEXT_PUBLIC_CONVEX_URL, CONVEX_SITE_URL, SITE_URL, CLERK_PUBLISHABLE_KEY, POSTHOG_KEY/HOST and SENTRY_DSN from their current NEXT_PUBLIC_* keys into VITE_* public keys for the candidate only. Change consumers to import.meta.env through the config module. Wire the mapped URL from the actual Convex deploy callback through both production and Preview builds, local integration, worktree setup and CI. Never expose the entire environment. Test missing configuration and scan client output for a synthetic server-only marker.

Reuse the 11 locale dictionaries through a framework-independent translation provider, as-needed prefix routing and explicit bypass routes. Verify EN, TH and all locale links, formatting, one dictionary per guest route, localized SEO, sitemap/robots, 404 before streaming, sign-in return and isolation between roles.
  8. Port localized public pages, then booking/pay/success and chat, then sign-in/up, display/dev and staff/admin. Move API messaging/image, admin/config-status and admin/chat/reply to Start server routes preserving auth, streaming/media and errors. Preserve marketing redirect status, bot flag and post-response recording, display no-store/no-referrer/noindex, static headers, image allowlist/size/quality and Sentry server/client source-map controls. Keep Convex HTTP routes, webhooks and cron ownership in Convex. Replace next/image with responsive picture/srcset output backed by Vercel Image Optimization (/_vercel/image). Mirror current formats, qualities and remote patterns in the adapter output. Verify a permitted remote URL, rejected host, layout dimensions and a local image. Wire @sentry/tanstackstart-react with client/server initialization and verify synthetic browser and server events in the test environment with source maps disabled when credentials are absent.

Check middleware, SSR direct URLs on reload, hydration parity, streaming, server-only secrets, native deps, cache and auth. Switch routing only after every manifest row has a passing result. Evict the exact test key before each miss or rotate a test-only cache namespace between misses. Record adapter hit/miss in a Preview-only response header and origin invocation counts.   11. During the room slice, check the pinned Vite 8.0.13 against the Start, Nitro, Clerk and Sentry peer/plugin ranges and capture a successful build with exact versions. Make bun check a dependable entry point

  • pnpm and Node 22 today
  • Wave 2

Developers and CI need the same failure signal after replacing the package manager.

Cause and evidence

The present check script invokes pnpm typecheck. scripts/run-checks.mjs spawns pnpm internally. Vercel, CI, local dev, worktree setup, heavy wrappers and tests also encode pnpm, Node or Next assumptions.

  • package.json
  • scripts/run-checks.mjs
  • Bun install and lockfiles
  • Bun check semantics
  • Bun on Vercel

Proposed fix

  1. Separate the package-manager cutover from the framework change. Pin an exact Bun version in toolchain setup and CI, import the current dependency graph into bun.lock, review optional/native dependencies, trusted install scripts and peer resolutions. On clean macOS and Linux perform bun install --frozen-lockfile twice, verify unchanged lockfile and smoke-test sharp, TypeScript native, oxlint, Vite/Vitest, Playwright, Convex CLI and codegen. Remove pnpm-lock.yaml in the atomic switch after a successful clean install.
  2. Define the package check script to run all three TypeScript projects (app, tests and Convex), type-aware oxlint and zero-warning ESLint, propagating the first failure. Use bun check as the public command. Test literal bun check and bun run check on the pinned binary. When using Bun’s native checker inside the script, use bun check --no-script -p <config> to avoid recursion and prove diagnostic parity with the repo’s TS 7 compiler. Keep the TS 7 invocations if native checker parity fails.
  3. Migrate nested command spawns, worktree setup/cache keys, CI jobs, Vercel install/build, preview-build, local dev/integration and docs in one toolchain change. Exercise bun run dev locally, keeping isolated Convex lifecycle, signal handling and seed guards. Keep Vitest projects and the shared heavy queue, two local workers and serial heavy commands. Map verify, verify:integration, test:booking-ui and test:e2e:smoke to explicit bun run commands. Retain knip, architecture score and benchmark gates. Refactor verify to call check once, then queued unit/build. Lint runs exactly once. Keep the old lock and pnpm version available in the OLD rollback environment only.
  4. Prove Bun as the Start SSR runtime separately on the target adapter. Record runtime identity and behavior in Preview, compare the same Start build under Node 22 and Bun. Keep Node available to tools that require it and the Convex-managed runtime for functions. If Bun SSR fails, record the blocker, use the last passing runtime for rehearsal and leave the Bun SSR cutover open.
  5. Review vercel.json and scripts/lib/scorecard-tests.mjs for nested package-manager invocations. Prove a second clean worktree can clone dependencies on APFS and install offline on the pinned Bun version. If cache reuse fails, rebuild from the frozen lock and record the setup cost.

Reduce measured database reads and bytes

  • Indexed reads confirmed
  • Wave 3

Find work that grows with unrelated rows or unused scene metadata. A new index or a reset merits its cost only if the data explains it.

Cause and evidence

getTourRooms already uses by_slug, then by_property, caps the result at 50, and sorts after the cap. getBySlug reads one active property, review stats and up to 20 reviews. The separate catalogue list can perform one stats lookup per active property, up to 100. Only trace data can place a given read on tour entry.

  • convex/catalog/properties.ts
  • convex/catalog/publicProperties.ts

Proposed fix

  1. Use the queryScale harness and getTransactionMetrics() to record documents and bytes read, rows returned, indexed ranges, JSON response bytes and elapsed handler time per endpoint. Seed 1/10/50 scenes, 0/20 reviews, 1/100 active villas, plus unrelated villas. Run the first-room, catalogue, booking-overlap and initialized inbox fixtures independently. Increase unrelated rows 10× with the selected villa fixed. Record writes, retries and recomputations on a scene edit. Use convex-test for deterministic counters. Collect read/write p95 timings on the isolated running backend, including unsuccessful/retried mutations.
  2. If DB bytes dominate, physically separate lightweight ordering/thumbnail summaries from hotspot/detail documents. Index summaries by property and explicit order with a stable tie-breaker, then read detail only for the visible scene. A projection after loading the same full documents changes wire bytes only. If transfer alone dominates, test a response projection against a separate ≥30% serialized-byte target, report DB reads unchanged, and pursue a measured DB hotspot separately. At 51 scenes, place the first tourRoomIds slug last by creation and assert exact configured order plus stable order of unlisted rooms through pagination. If choosing a hard max instead, validate every writer and explicitly reject oversize input.
  3. Allow dropping unused fields, rebuilding projections, changing endpoint shapes and reseeding synthetic data. For any projection enumerate create/edit/reorder/delete/archive and review writers, update atomically via the catalog model and compare against canonical rows after retries/concurrent edits. Record write amplification and consistency for every read saved.
  4. If a physical split changes the table count, document the change to the current 97-table scorecard target and regenerate the inventory. For new public registrations update convex/catalog/validators.ts and docs/architecture/phase3a-access-inventory.md, then prove the return and access gates.

Shorten the server and subscription path

  • Waterfall is a hypothesis
  • Wave 3

Reduce the time from a visitor’s request to the first scene data while preserving current live updates and access control.

Cause and evidence

Room SSR calls getVilla. Mounting the lazy viewer then subscribes to getTourRooms and starts a 3 s unavailable-state timer. The timer bounds a missing result. Actual delay may be cache misses, connection setup, query execution or unrelated browser work.

  • src/lib/server/villas.ts
  • src/components/tour/TourViewer.tsx

Proposed fix

  1. Trace a cache hit, miss, reconnect and outage on the direct link and the click path. Capture getBySlug and getTourRooms invocation counts, payload bytes, TTFB, first subscription result, reruns per unrelated edit and p50/p95. Replay 1 and 10 simultaneous opens plus edits at a fixed rate. Run an authenticated checkout and admin inbox sample to catch backend regressions. Edit price and description independently of scene data: getTourRooms reads the property document, so reevaluation may occur without a changed public scene result. Count reevaluations and actual client updates separately.
  2. If the late first subscription is causal, compare an intent-started live read with a request-scoped, uncached first-scene lookup for direct entry. Exclude scene data from shared SSR/HTML caches. Use SSR metadata only as a speculative asset hint. Require the authoritative active live scene before displaying the panorama. Reconcile by slug and stable scene ID, clear data on null, archive, sign-out or identity/route change, and cancel/dispose on close. Mount one live subscription per open viewer. Test ordinary room visits for zero panorama requests.
  3. If server spans are already small, publish the ceiling on potential tour savings. Optimize the highest demonstrated backend cost from the secondary flows separately, e.g. repeated reads in checkout or inbox under writes. Measure per operation and preserve the existing inbox budget and one durable write per messaging acknowledgement.
  4. Track Convex connection state explicitly. On disconnect mark the displayed subscription as unconfirmed. On reconnect require an authoritative result for the current property and identity before enabling interaction. A retained useQuery value alone cannot establish freshness. Use the same rendition selector for any speculative first-image hint as for the eventual viewer request.

Acceptance checks

Check actual authenticated and anonymous results on the isolated backend. Report measured DB, compute and wait contributions separately. Exercise three warm-tab cases with a second actor. Reorder with a still-valid explicit selection: keep that scene visible and update its previous/next neighbors. If the selected scene is removed, fall back to the first active one.   4. At stage C record the Start-only changes in initial client bytes and hydration-to-viewer-import time for ?tour=1. Use those figures as the phase 4 control so changes in renderer cost and framework cost remain identifiable.

Rehearse cutover and prove the gains

  • Implementation gate
  • Wave 4

A fast tour still needs working bookings, staff access and recoverable data after a breaking change.

Cause and evidence

The current Preview deploy builds a seeded backend before the frontend. Production uses a separate guarded path. A frontend rollback alone can fail against a changed schema or endpoint.

  • docs/architecture/phase1-reset-runbook.md
  • scripts/vercel-build.mjs

Proposed fix

  1. Before any breaking schema step, build a revision-specific operator manifest with OLD/NEW SHAs, schema and component inventories, ZIP and storage hashes, runtime/lockfile, deployment IDs, seed reference and exact target-bound commands tested on a fresh isolated target. Validate against both revisions. The historical Phase 1 runbook documents sequencing, and its 91/74-table ZIPs, seed path and reset script preconditions belong to a different schema. Generate new clear manifests for both sides. Disable outbound delivery on the rehearsal backend.
  2. Forward rehearsal: block traffic and callbacks, pause writes/cron, drain and verify scheduled work, export OLD including storage and prove its restore on an isolated OLD target. Clear OLD shapes while OLD is deployed, verify component and root state, deploy paused NEW and seed the verified empty target via maintenance/seed:seedAll (demo-resort). Compare counts, IDs/references, public assets and invariants. With ingress and external providers still gated, lift the internal pause for acceptance. Build the NEW frontend against accepted data. The existing production vercel-build invokes convex deploy: validate with a target-bound Preview or frontend-only build path and promote an already matched build, recording backend revision before and after. Record Vercel framework preset, output directory and alias before and after switching from Next to the tested Nitro output. Promote a staged production-target frontend built against the accepted backend with automatic alias assignment disabled. Save the old deployment ID for an alias reversal after data restoration. Keep Preview backend URLs out of the promoted artifact. On a shared target follow the runbook’s provider-specific pause/drain/reconciliation procedures for Stripe, LINE/Meta/WhatsApp, iCal, cron and outstanding jobs.
  3. Run tier 1 check:fast and focused tests per edit, then queued verify before handoff.
