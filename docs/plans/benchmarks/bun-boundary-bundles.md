## Dependency resolution and emitted modules

- The original lock installed separate physical `@clerk/shared@4.12.2` copies for `@clerk/nextjs` and `@clerk/react`. The exact direct pin made both resolve the same physical package. The checkout reduction was 14,530 gzip bytes.
- The Clerk-only build exposed another duplication. Radix Popper 1.2.8 and 1.3.7 each resolved a separate physical Floating UI React DOM 2.1.8 package and transitive DOM 1.7.6, core 1.7.5 and utils 0.2.11. Both Popper manifests already required `^2.0.0` for React DOM.
- Checkout's initial manifest included `0_z4bsysws.rn.js`, at 18,216 gzip bytes, and `0o7a8skc_fjbz.js`. Their Turbopack factories `[746798,186336]` and `[853660]` each contained the Floating UI geometry implementation signature `getBoundingClientRect`, `getClippingRect` and `getOffsetParent`. Across the initial checkout manifest the signature appeared in three factories with the Clerk-only lock and two with the final lock, matching the pnpm control. The 18,216-byte chunk also contained other Radix modules.
- With the exact `@floating-ui/react-dom@2.1.8` layout pin, both Popper versions resolve the same physical Floating UI package and transitive directories. Both continue to resolve React and React DOM 19.2.6 and satisfy their peer ranges. The checkout reduction was a further 7,027 gzip bytes. The lock was regenerated by Bun, and a fresh `bun install --frozen-lockfile --offline` preserved it byte for byte.

## Reproduce the route check

Use a clean checkout of the requested revision with its frozen dependencies, pinned binaries, and the dedicated local integration fixture.

```sh
VITEST_MAX_WORKERS=2 node scripts/heavy.mjs node scripts/local-integration.mjs -- \
  node scripts/bench/route-js-size.mjs --check-budgets --json output/routes.json
```
